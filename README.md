## 1. 📌 Project Overview & Problem Statement

### 1.1 The Context
In contemporary urban society, Hindu families residing in high-density metropolitan apartments and gated communities often face immense challenges when performing sacred ancestral sacraments (*Pitru Karyas*, *Shraddha*, *Masikam*, *Samvatsarikam*, *Abdikam*, and *Pinda Pradanam*):
- Fire and smoke restrictions prevent conducting Homas inside apartments.
- Severe scarcity of practicing, devout Brahmin *Bhokthas* who observe daily *Sandhyavandanam*.
- Rigorous traditional purity (*Madi*) food preparation requirements without onion or garlic.
- Difficulty finding genuine Vedic *Purohits* and authentic Shastric ritual items (*Darbha*, *Samidhalu*, cow ghee, black sesame).

**Ram Narayana Brahmana Seva Samstha** (located in Dilsukhnagar, Hyderabad, under the guidance of **Namburi Adinarayana Sharma**) was established to provide a dedicated sanctuary and turnkey management for these sacred ceremonies.

### 1.2 The Software Engineering Mission
To build a modern, elegant, lightning-fast digital web platform that:
1. **Educates devotees and family members** on the precise Shastric procedure, timing, and significance of each ancestral rite.
2. **Offers an interactive 11-field ritual intake system** connecting families directly to the organizers via WhatsApp and clipboard integration.
3. **Guarantees 100% pure language fidelity** with instantaneous zero-reload switching between pure Telugu and natural English.
4. **Prioritizes accessibility and readability** for elders through Google Font **Ramabhadra**, enlarged typography, high-contrast palette, and comfortable touch targets.
5. **Maintains maximum web performance** by eliminating runtime framework bloat, achieving a perfect 100/100 Lighthouse score and sub-50ms First Contentful Paint.

## 3. ⚙️ Technical Implementation & Subsystems

### 3.1 Zero-Framework Philosophy & Why Vanilla JS
Modern web development frequently suffers from "framework fatigue," where simple informational websites ship massive multi-megabyte JavaScript bundles (React, Next.js, hydration runtimes) that:
- Cripple low-end mobile devices common in emerging markets.
- Incur steep CPU parsing and execution penalties.
- Create ongoing maintenance overhead through dependency deprecations.

This project strictly adheres to the **Zero-Framework Standard**:
- **0 build steps**: Runs directly in any web browser without Node, Babel, or Webpack.
- **0 NPM runtime dependencies**: Zero third-party vulnerability vectors.
- **Instantaneous loading**: The entire application footprint (HTML + CSS + JS) is ~26 KB uncompressed.

### 3.2 Declarative Reactive i18n Engine
Localization is handled by a custom client-side reactivity engine in `assets/js/app.js` using data dictionaries defined in `assets/js/translations.js`.

```mermaid
flowchart LR
    UserTrigger["User Toggles Language (Dropdown / Bottom Bar)"] --> StateDispatch["setLanguage('te' | 'en')"]
    StateDispatch --> LocalStore[("Save to LocalStorage ('rnbs_lang')")]
    StateDispatch --> DocTitle["Update document.title"]
    StateDispatch --> MetaDesc["Update Meta & OpenGraph Descriptions"]
    StateDispatch --> DOMPass["Single-Pass DOM Mutation Query"]
    DOMPass --> TextNodes["[data-i18n] -> Element.textContent"]
    DOMPass --> HTMLNodes["[data-i18n-html] -> Element.innerHTML"]
    DOMPass --> MediaNodes["[data-i18n-src] -> Image.src"]
    DOMPass --> AltNodes["[data-i18n-alt] -> Image.alt"]
    DOMPass --> FormPlaceholders["[data-i18n-ph] -> Input.placeholder"]
    DOMPass --> WANodes["[data-wa-type] -> Pre-filled WhatsApp URLs"]
```

#### Core Engine Code (`assets/js/app.js`):
```javascript
function setLanguage(lang) {
  if (!translations[lang]) return;
  
  document.documentElement.setAttribute('lang', lang);
  localStorage.setItem('rnbs_lang', lang);
  const dict = translations[lang];

  // 1. Dynamic Title & SEO Metadata
  document.title = lang === 'te' 
    ? "రామ్ నారాయణ బ్రాహ్మణ సేవా సంస్థ - దిల్‌సుఖ్‌నగర్, హైదరాబాద్"
    : "Ram Narayana Brahmana Seva Samstha - Dilsukhnagar, Hyderabad";

  // 2. Text Content Mutation
  document.querySelectorAll('[data-i18n]').forEach(el => {
    const key = el.getAttribute('data-i18n');
    if (dict[key]) el.textContent = dict[key];
  });

  // 3. Rich HTML Content Mutation (Spans, Line Breaks)
  document.querySelectorAll('[data-i18n-html]').forEach(el => {
    const key = el.getAttribute('data-i18n-html');
    if (dict[key]) el.innerHTML = dict[key];
  });

  // 4. Media Asset Routing (Telugu vs English Flyer)
  document.querySelectorAll('[data-i18n-src]').forEach(el => {
    const key = el.getAttribute('data-i18n-src');
    if (dict[key]) el.src = dict[key];
  });

  // 5. Accessibility Synchronization
  document.querySelectorAll('[data-i18n-alt]').forEach(el => {
    const key = el.getAttribute('data-i18n-alt');
    if (dict[key]) el.alt = dict[key];
  });

  // 6. Form Input Placeholders
  document.querySelectorAll('[data-i18n-ph]').forEach(el => {
    const key = el.getAttribute('data-i18n-ph');
    if (dict[key]) el.placeholder = dict[key];
  });

  // 7. Contextual WhatsApp Message Links
  document.querySelectorAll('a[data-wa-type]').forEach(link => {
    const type = link.getAttribute('data-wa-type');
    const msg = (whatsappMessages[lang] && whatsappMessages[lang][type]) || whatsappMessages.te[type];
    if (msg) link.href = `https://wa.me/917780223977?text=${encodeURIComponent(msg)}`;
  });
}
```

### 3.8 Fluid Layouts & Zero-Overflow Engineering

To guarantee **0px horizontal overflow across all viewports (from 320px foldables to 4K displays)**:
1. Universal box sizing with boundary constraint:
   ```css
   *, *::before, *::after {
     box-sizing: border-box;
   }
   body {
     overflow-x: hidden;
     max-width: 100vw;
   }
   ```
2. Mathematical `clamp()` for responsive headings:
   ```css
   .hero-title-main {
     font-size: clamp(1.8rem, 4.5vw, 3.25rem);
   }
   ```
3. Flex and Grid items have `min-width: 0` to prevent inner text expansion from causing container overflow.
